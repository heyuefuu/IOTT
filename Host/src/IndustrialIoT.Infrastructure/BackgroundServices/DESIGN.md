# 连接池设计补充：埃斯顿保活

## 2026-09-30 — 持续发送协议层只读请求

**变更理由**：单次连接测试通过不等于持续通信正常。原连接池每 30 秒进行一次共享健康检查，空闲时无法满足 ER 控制器的接收报文看门狗。

**手册依据**：《ER 系列工业机器人 ModBusTCP 接口调试手册（RCS2 V2.0）》2.3 节，PDF 第 7 页 / 正文第 6 页：采集周期 >50 ms，响应超时 >150 ms；连接后超过 5 秒未收到客户端请求，服务器自动断开并重新监听 502 端口。4.2.1 节说明 40001 是心跳反馈，40252 控制心跳位维持时间，不是接收报文超时。

**变更内容**：连接池为 EstunRobot，以及品牌包含 Estun/埃斯顿的 ModbusTCP 连接启动独立任务，默认每 1000 ms 调用现有 `PingAsync`。可用 `ExtendedProperties["KeepAliveIntervalMs"]` 指定 51～4999 ms；缺失、无效或超出范围时回退到 1000 ms。

**决策依据**：

- 发真实的协议层只读请求，而非仅保持 TCP socket 存在。
- 使用现有驱动和读写锁，不建立第二条连接、不向命令寄存器写入。
- 每连接独立执行，不依赖 HTTP 请求存活或共享健康检查遍历速度；不提高其他品牌设备的默认请求频率。
- 取消令牌归连接池条目所有。释放条目时取消并等待保活任务结束，再关闭驱动，防止后台任务在释放后继续读或重连。
- 保留原有健康检查及失败清理策略，保活任务自身不移除或重新创建池连接。

**影响范围**：Host 连接池、埃斯顿驱动说明、连接生命周期回归测试。无新增运行时依赖、无数据库迁移、无控制器参数变更。仅更新前端不能使修复生效。

## 验证与限制

使用本机 Modbus 模拟服务器，配置更严格的 2.5 秒接收超时。修改前可复现单次测试成功后空闲断线；修改后覆盖默认周期、200 ms 自定义周期、50/5000 ms 越界回退、取消 HTTP 请求后继续保活、显式释放和 Host 停止后无报文/重连、其他品牌保持原频率。另运行 Modbus 恢复、PLC 共享连接采集与协议安全回归。

这不是硬实时调度保证。驱动慢请求、网络故障或锁等待仍会拉长实际报文间隔；不要将周期设置得接近 5 秒。Host 退出或连接被移除后，仍依赖原有连接/采集流程恢复。保活不会自动清除已有报警，也没有在现场硬件上验证；现场需确认实际控制器版本、部署版本和连续报文。
