# CAN 接入：SLCAN 串口适配器

当前驱动接入兼容 LAWICEL ASCII 命令的 SLCAN 串口适配器，收发 Classic CAN 11 位标准帧和 29 位扩展帧，单帧载荷为 0–8 字节。
这次实现与回归通过可控传输对端核对命令及接收路径；真实串口适配器、CAN 总线和客户设备尚未联调验证。

## 连接配置

选择 `CAN` 协议，`Port` 必须为 `0`。`ExtendedProperties` 示例：

```json
{
  "CanTransport": "SLCAN",
  "PortName": "COM3",
  "BaudRate": "115200",
  "CanBitRate": "500000",
  "CanFrameMaxAgeMs": "1000"
}
```

- `PortName`：Windows 串口名；未配置时使用连接配置中的 `Host`。
- `BaudRate`：串口波特率，默认 `115200`；不同于 CAN 总线波特率。
- `CanBitRate`：默认 `500000`；接受 `10000`、`20000`、`50000`、`100000`、`125000`、`250000`、`500000`、`800000`、`1000000`。
- `CanFrameMaxAgeMs`：接收帧最大缓存年龄，默认使用连接配置的 `ReadTimeout`，必须为正整数。
- 串口固定为 8 数据位、无校验、1 停止位、无握手。显式配置不同的 `DataBits`、`Parity`、`StopBits`、`Handshake` 会被拒绝。
- `ConnectTimeout` 覆盖打开串口及初始化；`ReadTimeout` 限制命令应答等待和无新帧时的读取等待。

连接依次发送 `C`、波特率命令（500 kbit/s 为 `S6`）、`O`，每条命令逐一等待确认。初始 `C` 收到 BEL 可继续初始化，配置和打开命令失败则连接失败。
健康检查发送 `F` 并读取状态，`F00` 仅表示适配器报告正常，不代表某个目标设备在线；非零状态返回检查失败。

## 点位地址及数据类型

| 地址 | 含义 |
| --- | --- |
| `STD:123` | 标准帧 ID `0x123`，11 位 ID 范围 `0x000–0x7FF` |
| `EXT:18FF50E5` | 扩展帧 ID `0x18FF50E5`，29 位 ID 范围 `0x00000000–0x1FFFFFFF` |
| `STD:123;endian=BE` | 数字类型按 big-endian 解码/编码 |
| `STD:123;endian=LE` | 数字类型按 little-endian 解码/编码，默认值 |

地址中的 ID 使用十六进制。标准帧和扩展帧分别缓存，即使数值 ID 相同也不会混用。
读取使用最近一次实际收到的对应数据帧，不主动发送 RTR，不把写入应答当成接收值。
缓存过期或尚未收到该 ID 时，等待新帧至 `ReadTimeout`；仍无可用帧时返回 `Bad` 及错误说明。

| 数据类型 | 要求 |
| --- | --- |
| `Bool`、`Int8`、`UInt8` | 载荷恰为 1 字节；`Bool` 读取值只能为 0 或 1，写入值为布尔值 |
| `Int16`、`UInt16` | 载荷恰为 2 字节 |
| `Int32`、`UInt32`、`Float` | 载荷恰为 4 字节 |
| `Int64`、`UInt64`、`Double` | 载荷恰为 8 字节 |
| `String` | 严格 UTF-8，编码后不超过 8 字节；字节序参数不改变字符串编码 |
| `ByteArray` | 原始 0–8 字节；字节序参数不改变数组顺序 |

整数越界、小数写入整数、无效 UTF-8、非有限浮点值和不匹配的载荷长度会失败，不截断或补齐载荷。
本版本不包含 CAN FD、CANopen、J1939、ISO-TP、多帧组包或 DBC 信号解析；需要这些能力的设备应另加上层协议适配。

## 写入结果与异常

写入 `STD:123` 的两字节数组 `AA BB` 会发送 `t1232AABB`；写入 `EXT:18FF50E5` 会发送 `T18FF50E52AABB`。
接收数据帧支持帧尾可选的四位十六进制适配器时间戳，RTR 帧不作为点位数据。

写入等待对应 `z`/`Z` 或空 CR 确认。成功仅表示适配器接受了发送命令，不证明远端设备已应用数据，也不等同于远端回读验证通过。
BEL 表示命令被拒绝，写入返回失败。发送后的命令超时、取消或串口接收断流会使会话进入故障状态并清除接收缓存，需重新连接，避免晚到应答被下一条命令误用。
空闲时收到意外应答也会使会话故障。重连前会先取消并关闭旧串口会话，等待旧命令退出，再建立新会话，避免旧命令的迟到异常影响新连接。
串口发送取消时会关闭端口并观察底层写任务的退出；测试使用可控传输栅栏核对会话顺序，真实串口驱动行为仍需硬件联调确认。
断开连接后不会返回上一会话的缓存值。

## 回归与现场验证

运行独立测试项目：

```powershell
dotnet run --project Host/tests/IndustrialIoT.Protocols.CAN.Tests
```

测试使用 `ISlcanTransport` 假对端，检查初始化命令、11/29 位 ID、时间戳、各类型字节序、无帧/过期/断开、非法帧、BEL、超时、取消和并发命令关联。
现场还需核对串口驱动、适配器 SLCAN 兼容性、总线波特率、接线与终端电阻，并由另一真实节点完成收发、断线恢复及设备应用结果回读。

协议依据：[LAWICEL CANUSB User Manual](https://www.canusb.com/docs/canusb_manual.pdf)，参见 Serial ASCII Protocol、S/O/C、t/T、F 与 Time Stamp 章节。
